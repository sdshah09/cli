New import_sync.go:

// syncImportedCheckpoints pushes checkpoints an import wrote. Import creates no
// commit, so the pre-push hook never fires and imported history would otherwise
// sit local-only until an unrelated `git push` (issue #1773).
//
// Runs regardless of whether this run imported anything new: turns imported
// while logged out stay queued, so a post-login re-run is the recovery path
// even though it reports "0 imported (N already imported)".
func syncImportedCheckpoints(ctx context.Context, w io.Writer, repo *git.Repository, remote string) {
    if !importLoggedIn() {
        return // warnIfImportNotSynced already explained why
    }
    pushed, pushDisabled, err := strategy.PushQueuedCheckpointRefs(ctx, repo, remote)
    switch {
    case err != nil:
        logging.Warn(ctx, "import: checkpoint sync failed", "error", err)
        fmt.Fprintf(w, "Note: could not sync imported history: %v\n", err)
    case pushDisabled:
        fmt.Fprintln(w, "Checkpoint pushing is disabled in settings; imported history stays local.")
    case pushed == 0:
        // already synced
    default:
        fmt.Fprintf(w, "Synced %d checkpoint(s) to %s.\n", pushed, remote)
    }
}

Plus --remote defaulting to origin, and the same two lines in setup_import.go:245 so entire enable gets it too.

That's the whole thing. ~40 lines.

Why this shape

PushQueuedCheckpointRefs already exists (manual_commit_push.go:300) with the exact signature needed — (pushed, pushDisabled, err) — and doctor_migrate.go:60-115 is a shipped precedent doing foreground "push now" with it. Copy that switch.

It sidesteps the empty-remote hazard entirely. Checkpoint refs live under refs/entire/, not refs/heads/, so GitHub can never pick one as a default branch. The code says so at :78-82. That's why this needs no guard, while the v1 branch does.

It doesn't touch the idempotency logic. Leave existing[] at agentimport.go:237 alone. The 6 refs in my repro are already queued — draining the queue recovers them whether or not this run imported anything.

Scope: git-refs only

Since #1900, every new repo is git-refs. Pre-#1900 repos on git-branch still need PrePush (queue-less, uses hasUnpushedBranchRef) — but it carries the empty-remote hazard and PrePush passes protect=false, so it needs care. Leave it out of this PR and say so; the legacy path still syncs via the hook as it does today.
